# WRITING_RULES.md — 文章規則

本書は Marketing Report Skill の **Step 10（レポート生成）直前に必読**の文章規則である（`SKILL.md` §0 準拠）。目的は、品質基準1「結論ファースト」・基準5「経営層向け」・基準6「投資家向け対応」・基準9「そのまま共有可能」を、書き手の裁量に依存せず判定可能なルールとして固定することにある。構成は `TEMPLATE.md`、見た目は `STYLE_GUIDE.md`、出力形式は `OUTPUT_RULES.md` が受け持ち、本書は「文そのもの」の規則だけを扱う。

## 1. 大原則（3つ）

### 1.1 結論ファースト

- **章・節・段落のすべてで、第1文は結論**にする（品質基準1の判定そのもの）。
- 判定: 各章の第1文だけを抜き出して並べたとき、レポートの主張の骨子が再現できれば合格。背景説明・経緯・定義から始まる章は不合格。
- 例外は「前提条件」「出典一覧」等の参照用の章のみ。

| 悪い例 | 良い例 |
|---|---|
| 「近年、○○市場は大きな変化の中にある。まず市場の定義から確認したい。」 | 「○○市場への参入を推奨する。市場は年率12%で成長し、競合は高価格帯に偏在しているためだ。」 |

### 1.2 ピラミッド構造

- すべての主張を「**結論 → 根拠（2〜4点）→ 詳細（データ・出典）**」の3層で書く。
- 判定: 任意の結論文に対し「なぜそう言えるか？」と問うたとき、直後に根拠が現れるか。根拠が3段落先にある構成は不合格（並べ替える）。
- 根拠は MECE を意識するが、網羅より「意思決定に効く2〜4点」への絞り込みを優先する。

### 1.3 So What テスト

- すべての文について「**この文は読者の意思決定を変えるか？**」を問う。変えない文は削除するか付録へ移す。
- 判定: 文を削除してもレポートの結論・推奨・数値根拠が損なわれないなら、その文は不要。
- 特に「事実の羅列」に注意: 事実には必ず解釈（だから何か）を添える（`ANALYSIS_FRAMEWORK.md` §4 の3段形式と同じ）。

## 2. 文の規則

| # | ルール（判定文） | 悪い例 → 良い例 |
|---|---|---|
| S-01 | 1文は**60文字以内**を目安とする。80文字を超えた文は必ず分割する | 長文1つ → 短文2つに分割 |
| S-02 | 1段落は**3文以内**。4文以上になったら段落を分けるか箇条書きにする | — |
| S-03 | 一義的に読める文だけを書く。係り受けが2通りに読める文は書き直す | 「急成長する競合の市場」→「競合が急成長している市場」/「競合が持つ、急成長中の市場」のいずれかに確定 |
| S-04 | **能動態を優先**する。動作主が重要な文で受動態を使わない | 「値上げが実施された」→「競合A社が値上げした」 |
| S-05 | **二重否定禁止** | 「不可能ではない」→「可能である（確信度: 低）」 |
| S-06 | 1文に主張は1つ。「〜だが、〜であり、〜なので」の連結文は分割する | — |
| S-07 | 修飾語は被修飾語の直前に置く | 「大きく売上に貢献した」→「売上に大きく貢献した」 |
| S-08 | 体言止めは表・箇条書き内のみ許可。地の文では使わない | — |

## 3. 語彙規則

### 3.1 表記ゆれ統一表

同一レポート内での混在を禁止する。以下の使い分けを標準とする（案件固有の用語は前提条件章に用語表を追加する）。

| 統一表記 | 使い分けの定義 | 使わない表記 |
|---|---|---|
| ユーザー | 製品・サービスを**利用する人**（未課金含む） | ユーザ、利用者（文脈統一のため） |
| 顧客 | **対価を支払う**個人・企業（契約主体） | お客様、クライアント |
| サービス | 提供形態を指すとき（SaaS、サブスク等の**事業側視点**） | — |
| プロダクト | 機能・UXなど**作るもの側視点**のとき | 製品（ハードウェアを除く） |
| 施策 | 実行可能な粒度の打ち手（Step 7 の単位） | 打ち手、アクション（本文では施策に統一） |
| 競合 | 分析対象として定義した企業（前提条件章で列挙） | ライバル、競合他社（「他社」は冗長） |
| 市場規模 | 金額ベース。数量ベースの場合は「市場規模（数量）」と明記 | マーケットサイズ |
| 継続率 | リテンションの訳語として統一。定義式（D7/D30等）を初出時に明記 | 定着率、残存率 |
| 解約率 | チャーンレートの訳語として統一 | 離脱率（ファネル離脱と区別するため） |
| 前年比 | YoY の訳語。「前年同期比」と区別して使う | 昨対比 |

- V-01: 上表にない語で表記ゆれが起きうるもの（例: 「Webサイト/ウェブサイト」）は、初出の表記に全体を統一する。
- V-02: 英数字は半角に統一する。単位（%・円・億円）の直前にスペースを入れない。

### 3.2 カタカナ語の扱い

- K-01: カタカナ語・英語略語は**初出時に補足**を付ける。形式: 「リテンション（継続利用率）」「CAC（顧客獲得コスト: Customer Acquisition Cost）」。
- K-02: 2回目以降は補足なしで使用してよい。ただし章をまたいで久しぶりに登場する場合（10ページ相当以上の間隔）は再度補足する。
- K-03: 日本語で同じ精度で言えるカタカナ語は日本語にする（「アグレッシブな成長」→「積極的な成長」）。固有のフレームワーク名・指標名（AARRR、NPS等）はそのまま使う。

### 3.3 専門用語

- K-04: 専門用語は**初出時に1行定義**を付ける（本文中の括弧書き、または脚注）。品質基準5「専門用語に補足がある」の判定対象。
- K-05: 読者が経営層・投資家の場合、社内用語・チーム内略語の使用を禁止する（例: 社内プロジェクトコードネームは正式名称に置換）。

## 4. 数値の書き方

| # | ルール（判定文） | 悪い例 → 良い例 |
|---|---|---|
| N-01 | 「多い/少ない/大きい/小さい/高い/低い」を単独で使わない。**必ず数値か比較対象**を添える | 「解約率が高い」→「解約率は月次3.2%で、業界中央値（推定1.5%）の約2倍」 |
| N-02 | 「約」は丸めた実測値に使う（約840億円 = 実測を丸めた）。「推定」は算出した値に使う（推定840億円 = 自ら計算した）。混用しない | — |
| N-03 | %には**分母を明示**する。分母のない%は書かない | 「40%が満足」→「レビュー60件中40%（24件）がポジティブ」 |
| N-04 | 増減は「前年比/前月比/前四半期比」のいずれかを明記する。基準のない「20%増」を禁止 | 「売上20%増」→「売上は前年比+20%（2025年度→2026年度）」 |
| N-05 | 期間比較は起点と終点の両方を書く | 「近年2倍に」→「2023年→2026年で2.1倍」 |
| N-06 | 数値の分類（事実/推定/仮定）と出典・基準日は `RESEARCH_METHOD.md` §5 に従う | — |
| N-07 | 桁の大きい数値は3桁区切り+適切な単位（12,400百万円 → 124億円）。1つの表内で単位を混在させない | — |
| N-08 | 小数点以下の精度をソースの精度以上にしない（ソースが「約8割」なら 80.0% と書かない） | — |

## 5. 読者別の表現規則

### 5.1 経営層向け

- E-01: **「〜と思われる」「〜かもしれない」の乱用禁止。** 不確実な主張には確信度を**高/中/低**で明示する（確信度の根拠Tierとの対応は `RESEARCH_METHOD.md` §2.3）。1章あたり「思われる」は2回まで。3回以上出たら確信度表記に書き換える。
- E-02: 選択肢は**必ず比較表**で示す。文章で「A案とB案がありB案が良い」と書くだけの提示を禁止する。比較軸はインパクト/実現性/リスク/投資額（`SKILL.md` Step 6 準拠）。推奨しない案も表に残す。
- E-03: **悪いニュースを隠さない。** リスクの過小表現（「軽微な懸念」「多少の課題」）を禁止し、影響額・発生確率（高/中/低）・対応策をセットで書く。
- E-04: 判定: 経営層が読むのは Executive Summary と比較表と Next Actions である。この3つだけで意思決定できる状態になっているか。
- E-05: 「検討する」「推進する」等の動作が特定できない動詞を推奨アクションに使わない。「誰が・何を・いつまでに」（品質基準7）で書く。

### 5.2 投資家向け

- I-01: 市場規模は **TAM/SAM/SOM** の3層で語る。TAM（獲得可能な最大市場）/ SAM（提供モデルで到達可能な市場）/ SOM（現実的に獲得可能な市場）。各層に算出式と出典を付ける（`RESEARCH_METHOD.md` §5.2 フェルミ推定の作法準拠）。
- I-02: 成長は **CAGR（年平均成長率）** で語る。算出期間（例: 2023-2026）を必ず併記する。単年の伸び率をCAGRと呼ばない。
- I-03: 収益性は**ユニットエコノミクス**で語る: LTV（顧客生涯価値）、CAC（顧客獲得コスト）、LTV/CAC比（3.0以上が一般的な健全ライン、と基準値も添える）、CAC回収期間（月数）。定義式を初出時に明記する。
- I-04: 実績と予測を視覚・表記で区別する（予測値には「（予測）」を付け、グラフでは実線/破線を分ける — 図の規定は `STYLE_GUIDE.md`）。
- I-05: リスク章を省略しない。市場・競合・実行・規制の4分類で最低1件ずつ検討する（該当なしの場合は「該当なし」と判断根拠を書く）。

## 6. 禁止表現リスト

以下の表現をレポートに書いてはならない。検出したら右列の対応をとる。

| 分類 | 禁止表現の例 | 対応 |
|---|---|---|
| 煽り表現 | 「今すぐやらないと手遅れ」「バスに乗り遅れるな」「革命的」「ゲームチェンジャー」 | 事実と数値に置換（緊急性は期限とその根拠で示す） |
| 根拠なき最上級 | 「圧倒的」「唯一無二」「業界No.1」「最強」「完璧」 | 出典付きの順位・シェア・比較値に置換。出典がなければ削除 |
| 責任回避の乱用 | 「〜の可能性も否定できない」「一概には言えないが」「諸説あるが」 | 確信度（高/中/低）+根拠の明示に置換（E-01準拠） |
| 内容のない形容詞・副詞 | 「しっかり」「きちんと」「積極的に」「適切に」「柔軟に」「随時」 | 具体的な行動・数値・頻度に置換（「随時確認」→「週次で確認」） |
| 主語の消えた断定 | 「〜と言われている」「〜とされている」 | 誰が言っているか（出典）を明示。出典がなければ削除 |
| 曖昧な規模感 | 「多数の」「一部の」「かなりの」 | 数値+分母に置換（N-01/N-03準拠） |

- 判定: Step 11 の校正時に上表の語をレポート全文から検索し、検出ゼロで合格。

## 7. 要約の書き方

### 7.1 Executive Summary の型

本文完成後に**最後に書く**（`SKILL.md` Step 10 準拠）。1ページ以内（目安600字+表/箇条書き）。以下の4ブロックをこの順で構成する（品質基準2「結論・根拠・推奨・数字」に対応）。

```markdown
## Executive Summary

**結論（1文）**: 例「○○市場への2027年参入を推奨する（確信度: 高）。」

**根拠（3点）**:
1. （市場: 数値付きの根拠 — 例「市場はCAGR12%で成長し2028年に推定1,200億円」）
2. （競合: 数値付きの根拠 — 例「競合5社は高価格帯に集中し、月額1万円未満の低価格帯は空白」）
3. （自社: 数値付きの根拠）

**推奨アクション**: （誰が・何を・いつまでに、上位3件のみ）

**主要数値**: TAM/SAM/SOM、目標KPI、必要投資額、回収見込み（表1枚に集約）
```

- 判定: Executive Summary 内のすべての数値が本文に登場し、本文と一致していること（サマリーだけの新情報は禁止）。

### 7.2 各章末尾サマリーの型

本文の主要章（分析・戦略の章）の末尾に、以下の2行型サマリーを置く。

```markdown
> **この章の要点**: （章の結論を1文で再掲）
> **次章への接続**: （この結論が次章の何を導くか1文で）
```

- 判定: 章末サマリーの1文目が、章の第1文（結論）と同じ主張になっていること（ズレていたらどちらかが間違っている）。

## 8. 見出しの書き方

- H-01: **節見出しはメッセージ見出し（主張を含む見出し）を推奨**する。名詞止めの見出しは中身を読まないと結論が分からない。

| 名詞止め（避ける） | メッセージ見出し（推奨） |
|---|---|
| 競合分析 | 競合は高価格帯に集中、低価格帯は空白 |
| 市場動向 | 市場はCAGR12%成長、牽引役は中小企業のDX需要 |
| リスク | 最大リスクは規制変更、影響額は年商の8% |

- H-02: ただし**章タイトルは `TEMPLATE.md` の標準章名を維持**する（章の対応関係を全レポートで揃えるため）。メッセージ化は章内の**節見出し**で行う。
- H-03: メッセージ見出しは40文字以内。数値を1つ含めることが望ましい。
- H-04: 見出しの階層は3階層（##/###/####）までとし、####の下に見出しを作らない（深い階層は構成の失敗を示す — 分割か統合を検討）。
- H-05: 判定: 節見出しだけを目次として抜き出したとき、レポートのストーリーが読めれば合格。

## 9. 校正チェック（セルフチェック手順）

Step 11（`CHECKLIST.md`）の前段として、文章面のセルフチェックを以下の手順で行う。品質基準9「誤字・表記ゆれ・リンク切れ・未完成箇所ゼロ」の文章部分を担う。

### 9.1 手順（この順で3周する）

| 周回 | 観点 | 具体的な操作 |
|---|---|---|
| 1周目: 機械的検出 | 誤字・禁止語・プレースホルダ | §6 の禁止表現、および「TODO」「TBD」「XXX」「■」「（仮）」「Lorem」を全文検索し、検出ゼロを確認する |
| 2周目: 表記ゆれ | §3.1 の統一表 | 統一表の「使わない表記」列の語を全文検索し、検出ゼロを確認する。数値の単位・桁区切りの混在（N-07）を表ごとに目視確認する |
| 3周目: 冗長と重複 | 文・段落レベル | 下記 9.2 のチェックリストを各章に適用する |

### 9.2 冗長表現・重複段落のチェックリスト

- [ ] 「することができる」→「できる」、「〜という」の乱用、「〜において」→「〜で」など冗長表現を圧縮した
- [ ] 同じ主張を2箇所以上で述べている段落がない（Executive Summary と章末サマリーの意図的な再掲を除く）
- [ ] 各段落の第1文だけを読んで意味が通る（1.1 の判定）
- [ ] 80文字超の文がない（S-01）
- [ ] 4文以上の段落がない（S-02）
- [ ] すべての%に分母がある（N-03）
- [ ] 「思われる」が1章2回以内（E-01）
- [ ] 見出しだけでストーリーが読める（H-05）

### 9.3 合格判定

- 9.1 の3周がすべて完了し、9.2 の8項目が全チェック済みであること。1項目でも未達なら修正して該当周回をやり直す。
- 本チェックは文章面のみを対象とする。構成・図表・出典の最終判定は `CHECKLIST.md` の9領域で行う。
